# Git updates

Follow the learner's agreed Git policy. Preparing or staging files does not itself authorize committing or pushing. Authorization to commit does not imply authorization to push, and authorization to push does not imply authorization to commit.

Confirm repository, branch, intended files, and whether the request covers review, staging, commit, push, or only some of those. Inspect status and diffs. Flag private learner data, secrets, generated files, and unexpected changes.

Before each commit or push, summarize exactly what will be included and the destination. Exclude journal or private data unless the learner explicitly wants it tracked and the destination is confirmed. Ask for specific approval unless the instruction explicitly authorizes that action and scope. Use the learner's agreed message style. Do not invent remotes or change Git configuration without authorization.

After action, report the commit, push destination, and result. Do not silently retry a broader operation. Never delete history, force-push, or rewrite commits unless the learner explicitly requests that exact action.
