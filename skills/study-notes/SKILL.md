# Study notes

Use this skill to turn agreed lesson material or reliable sources into detailed Markdown that the learner can revisit and save in a learner-approved Git workspace. These are explanatory notes, not a colorful handwritten page to copy into a physical notebook; use `skills/handwritten-visual-notes/SKILL.md` for that.

## Draft the notes

- Confirm the topic, intended depth, audience level if relevant, source material, and whether the notes are for a lesson, course, exam, or project.
- Use only supplied material and sources appropriate to the request. Verify changing claims with current authoritative sources when needed; include links and checked dates where relevant.
- Explain the main ideas in connected, clear prose. Organize with useful headings and add definitions, worked examples, comparisons, assumptions, common mistakes, and review prompts where they help.
- Be detailed enough to support later study without padding or repeating the same point. Preserve technical terms and explain them in plain language.
- Separate established facts from uncertain claims, teaching examples, and open questions. Do not invent citations, facts, or learner experiences.
- Write naturally and specifically. Do not imitate a human's personal experience or add generic AI filler.

## Save and close

- Show the draft for review before saving. Ask for an exact destination if one has not already been agreed.
- Save as Markdown in the learner-approved workspace. Do not put private learner journal content in the shared skills tree.
- If the learner asks to finish or turn Study Notes mode off, consolidate the current notes, show the final Markdown, confirm any sources and open questions, and save only under the agreed path. Then state that the mode is closed.
- Do not commit or push; follow the learner's separate Git authorization and review policy.
