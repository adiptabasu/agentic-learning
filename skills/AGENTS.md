# Canonical skills guidance

The skills/ tree is the portable source of truth for reusable learning workflows.

- Store each canonical skill at skills/<skill-name>/SKILL.md.
- Use Agent Skills-style YAML frontmatter with matching name and folder name, plus a concise description.
- Keep each skill focused on one coherent workflow. Add references only when they materially improve the workflow.
- Make the smallest coherent skill change that satisfies the request; preserve unrelated skill content and avoid broad refactors.
- Do not put private learner journals or topic workspaces in this shared tree.
- Tool-specific copies may be needed for discovery. Preserve the canonical source, identify adapter paths, and explain how copies stay synchronized.
- Before changing the tree or adding host paths, inspect the repo and present the intended change when it affects the agreed structure.
- Do not promise discovery or slash invocation for a host until its current official documentation supports that claim.
